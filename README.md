# 木魚

一個網頁法器。敲一下，響一聲，功德 +1。滿 108 下，和尚走出來鞠一個躬，然後重新開始。

```bash
npm install
npm run dev
```

## 兩種法器

**木魚**：供在蒲團上，旁邊躺著一支槌。可以自由連敲，要多快有多快。

**念珠**：一手拿著，拇指每一下往前推一顆。佛珠正好 108 顆，所以「撥一顆」和「一輪」是同一件事——珠環每敲一下轉 `360/108` 度，第 108 下剛好轉滿一圈回到原點，母珠回到拇指底下。**「108 回到原點」不是另外寫的規則，是這串珠子的幾何。**

兩者共用同一個功德數，換法器不會歸零。聲音不同：木魚是中空木腔（低沉、有餘韻），念珠是兩顆珠子相碰（實心、乾、短），同一套合成器不同參數。

## 這是什麼形態

**單次型**：計數是一次專注的節奏感，不是跨時間累積的資產。關掉分頁就歸零。

這個決定消滅了帳號、同步、備份、排行榜、跨裝置合併的一切需求，也消滅了後端——原始構想裡的「串接後端」，追問到底之後只剩「每日經文／樣式」這類純內容，那寫成原始碼裡的常數就夠了。只有當你想在**不重新部署**的情況下更新內容時，抽成獨立 JSON 才划算。

完整的決策紀錄與辯論過程：https://claude.ai/code/artifact/585a7f66-1096-40f5-b2cc-8b60a02d4435

## 結構

| 檔案 | 職責 |
| --- | --- |
| `index.html` | 三個 SVG：木魚、念珠與手、和尚。和尚的腰與頸是兩個旋轉支點 |
| `src/counter.ts` | 計數。同步讀取、記憶體累加、延遲落盤 |
| `src/audio.ts` | 音訊。合成兩種音色、疊加播放、處理 iOS 的靜音與中斷 |
| `src/mala.ts` | 108 顆珠子的幾何 |
| `src/main.ts` | 接線、法器切換、敲擊回饋、108 的儀式 |

`counter.ts` 對外只有三個函式，讀取永遠同步、永遠不失敗：

```ts
getMerit(): number
tap(n = 1): void
subscribe(cb): () => void
```

## 幾個不明顯的地方

**聲音不等動畫。** 敲下去的瞬間就響，演出才慢慢跑。樂器的即時性不能讓給演出，所以 `strike()` 和 `tap()` 在 `pointerdown` 當下就執行。

**儀式有一道逾時保險。** 擋輸入的設計只有一種失敗模式，而且是致命的：動畫的 `finished` 沒有 settle，`inRite` 就永遠是 `true`，法器從此敲不動。分頁切到背景會讓 WAAPI 停止推進、動畫被取消會 reject、元素被抽換則兩者都不會發生。三秒多、橫跨六個動畫的儀式暴露面很大，所以 `RITE_GUARD_MS` 不是防禦性冗餘。儀式還帶一個 token，收場後任何遲到的步驟都會認出自己已經過期。

**和尚最多鞠 30 度。** 腰轉 30°、頭再多 12° 且慢半拍（二次動作）。再多就會在後頸露出破綻——`scratchpad/poses.mjs` 那支腳本會從 `index.html` 直接抽出 SVG 排成幾個角度，改造型時可以拿來對照。

**木魚旁邊那支槌是必要的。** 沒有它，一個對稱的圓形色塊加上下方的暗色開口，人腦一定讀成笑臉——這是 pareidolia，不是配色問題。蒲團與槌把它錨定成法器。同理，念珠那隻手不畫手掌：封閉的團塊加上兩根突起也會讀成臉。食指畫在珠子之前、拇指畫在珠子之後，珠串被前後夾住，「握著」就是這樣讀出來的。

**音效是合成的，不是音檔。** `audio.ts` 的 `render()` 用一組非諧和分音加一段極短的噪音 transient 合出聲音，所以這個專案沒有任何資產檔案。想換成真實錄音，把 `render()` 換成 `fetch` + `decodeAudioData`，下游一行都不用動。

**每次敲擊都檢查 `ctx.state`。** 不是只在首次解鎖時做一次。這同時處理了 user gesture 解鎖，以及 iOS 上被來電／Siri 打斷後 AudioContext 進入 `interrupted` 且不會自動恢復的狀況。

**用 `sessionStorage` 而不是純記憶體。** iOS Safari 會主動丟棄背景分頁，切出去回個訊息再回來頁面就重新載入了。純記憶體在那一刻歸零，那是 bug 不是設計。sessionStorage 重新載入時保留、分頁關閉時清空，語意剛好吻合「單次型」。

**綁 `pointerdown`，不綁 `click` 也不綁 `touchstart`。** click 要等 touchend 判定，手感慢半拍；touchstart 在 document 層預設 passive，`preventDefault()` 無效。鍵盤操作另外用 `keydown` 補回來。

**法器上那四行 CSS 是防護不是裝飾。** 連續點擊必然觸發 iOS 的 double-tap zoom、長按放大鏡、文字選取藍框。

## 待實機驗證

在 iPhone 上測這兩件事，兩件都沒有人確認過：

1. `navigator.audioSession.type = 'playback'` 是否確實讓 Web Audio 繞過實體靜音開關。失敗症狀是「使用者敲了半天沒聲音」，代價很高。
2. `sessionStorage` 在分頁被 iOS 丟棄後、系統還原分頁時是否確實保留。最壞情況是退回純記憶體的行為，沒有額外損失。
